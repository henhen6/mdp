# 接口权限设计

> 本文档由头脑风暴确认后成文（2026-09-27），是接口权限功能的最终需求基线。
> 接口权限分为配置、授权、拦截三阶段；与《用户角色组织权限体系设计.md》冲突时，
> 以本文档为准。

## 0. 设计目标

实现按"资源（菜单/目录/按钮）关联接口"的接口级权限控制：

1. **配置期**：在菜单管理界面为每个菜单/目录/按钮关联接口（扫描选择或手动录入通配符）。
2. **授权期**：角色授权逻辑零改动——勾选资源即视为拥有其关联接口的访问权。
3. **拦截期**：单体版经 `TokenContextFilter`（md-common-config）、微服务版经网关
   `AuthenticationSaInterceptor`（inner-gateway-server）统一拦截判定。

## 1. 决策汇总（头脑风暴确认）

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 未配置接口的默认行为 | **全局开关可配**（放行/拒绝，复用 `IgnoreProperties` 的 `authEnabled` + `notConfigUriAllow` 语义） |
| 2 | 数据模型 | 推翻旧 `mdc_resource_uri`（无数据无代码、uk(controller) 有硬伤），**重建为单表 `mdc_resource_api`** |
| 3 | 定义表与关联表是否拆分 | **不拆分**。懒增长语义下一接口挂 N 资源 = N 行，删行即解关联无孤儿；元数据（name/controller）冗余的漂移代价可忽略 |
| 4 | 接口候选数据源（微服务版） | **方案 A：按应用分别拉取**——前端经 `findOnlineServicePrefix` 拿服务前缀，调对应服务的 `/anyone/systemApiScan`；单体版提供等价端点返回固定前缀，前端零分支 |
| 5 | 微服务版拦截数据来源 | **网关自治直查库**（CacheOps 缓存 + 回源 Db 直查，同 `DataScopeProviderImpl` 模式；与 console 共享 Redis key，失效由 console 写操作执行） |
| 6 | 通配符语法 | 凡是 AntPathMatcher 支持的合法路径模式都允许（尾缀 `/**`、中段 `*`、`?`），入库只校验"以 `/` 开头、非空" |
| 7 | 内置账号 | **运营者（绑定启用中 OPERATIONS_ADMIN 角色的用户）豁免一切接口权限**，在缓存B加载器中短路判定 |
| 8 | 接口初始化 | **不初始化、"选择即入库"懒增长**：定义表只记录"被配置过"的接口，与扫描实时数据解耦 |

## 2. 三阶段数据流

```
① 配置期（菜单管理界面）
   菜单/目录/按钮 → Tab2【关联接口】→ 选择（扫描）或 新增（手录通配符）
   → mdc_resource_api（resource_type + resource_id + uri + request_method）
        ▼
② 授权期（角色管理/角色模板，零改动）
   勾选资源 → mdc_role_resource_rel（现有表，不动）
        ▼
③ 拦截期（请求进入）
   路径归一化 → 全量已配置接口集判定"是否纳管"
   → 用户放行集（用户→角色→资源→接口 多跳并集）判定"是否有权"
```

**生效链**：`角色 → 资源 → 关联接口 → 请求 uri+method 匹配 → 放行/拒绝`

## 3. 数据模型（一删一建）

### 3.1 新表 `mdc_resource_api`（接口权限表）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT | 主键，雪花 ID |
| resource_id | BIGINT NOT NULL | 资源id（菜单表id；按钮即 menu_type=50 的菜单行，id 空间统一） |
| uri | VARCHAR(255) NOT NULL | 接口路径（裸路径，Ant 风格通配） |
| request_method | VARCHAR(10) NOT NULL | GET/POST/PUT/DELETE/ALL |
| name | VARCHAR(255) | 接口名（扫描取 @Tag+@Operation，手录手填） |
| controller | VARCHAR(255) | 来源类名（手动录入为 NULL） |
| application_name | VARCHAR(255) | 来源服务（手动录入为 NULL） |
| is_input | BIT(1) DEFAULT b'0' | 是否手动录入（通配符接口为 1） |
| created_at / created_by / updated_at / updated_by | — | 审计字段 |

- 唯一键 `uk_uri_method_res (uri, request_method, resource_id)`：
  同一接口可挂 N 个资源（N 行），同资源下防重复配置。
- 索引 `idx_resource_id (resource_id)`：按资源回显与加载器反查。
- **resource_type 字段已下线（2026-09-27）**：按钮即菜单行（menu_type='50'），
  resource_id 统一菜单表 id 空间，类型字段冗余（回显/匹配/级联均只按 id）。

### 3.2 删除清单

| 对象 | 说明 |
|---|---|
| `mdc_resource_uri` 整表 | 旧设计，无数据无代码 |
| `mdc_resource_button` 整表及 `ResourceButton*` 9 个文件 | 历史死代码（仅 1 条测试垃圾数据；按钮由菜单行承载） |

## 4. 配置期

### 4.1 前端交互（web-console 菜单管理页）

右侧面板改为 a-tabs：**Tab1 基本信息**（现有 `detail.vue` 原样嵌入）、**Tab2 关联接口**。

Tab2 内容：
- 工具栏：【选择接口】【新增接口】；列表列：接口名 / URI / 方式 / 来源（扫描|手录）/ 操作（删除，二次确认）。
- 切换树节点（菜单/目录/按钮）时按 `resource_type + resource_id` 重新拉取回显。

【选择接口】抽屉：
1. 顶部服务前缀切换：微服务版调网关 `findOnlineServicePrefix` 拿 `{服务名: 前缀}`；
   单体版由 boot-server 提供等价端点返回固定前缀（前端代码零分支）。
2. 按前缀调 `/api/{前缀}/anyone/systemApiScan`，按 Controller 分组展示候选（名称/URI/方式）。
3. 已关联的默认勾选且置灰；保存调 `bind`。

【新增接口】弹窗：手填 URI（Ant 风格通配）、方式下拉（GET/POST/PUT/DELETE/ALL）、接口名。

### 4.2 后端端点（新增 `ResourceApiController`，console-web）

| 端点 | 方法 | 说明 |
|---|---|---|
| `/permission/resourceApi/list` | GET | 按 resourceId 查已关联接口（Tab2 回显） |
| `/permission/resourceApi/save` | POST | 手动录入一条（is_input=1） |
| `/permission/resourceApi/bind` | POST | 选择模式批量入库：入参为扫描接口数组，按 uk 去重（已关联跳过，新增插入），幂等 |
| `/permission/resourceApi/delete` | POST | 按 ids 删行 |

候选数据源不经后端代理，前端直连各服务扫描端点。

### 4.3 校验与级联

- URI 以 `/` 开头、非空；匹配语法完全交给 AntPathMatcher，不额外限制通配位置。
- 手动录入与扫描接口撞 uk 时按已存在处理（幂等）。
- 菜单/按钮删除时，在 ResourceMenu/ResourceButton 删除逻辑中级联删 `mdc_resource_api` 行，防悬挂关联。

## 5. 授权期（零改动）

角色管理/角色模板页面不改任何逻辑。授权落库仍是 `mdc_role_resource_rel`，
运行时由拦截器加载器多跳解析：

```
例：角色「财务专员」勾选了【用户管理】菜单
  → mdc_role_resource_rel 有 (roleId, MENU, 用户管理id)
  → 用户放行集加载：用户管理id 在 mdc_resource_api 关联了
    /organization/user/page、/organization/user/getById
  → 这两个接口对该角色下所有用户放行
后配红利：之后给【用户管理】新关联 /organization/user/export
  → 无需重新授权，缓存失效后自动放行
```

权限集合委派链自然传导：角色管理能勾的资源范围被权限集合约束，接口权限随资源走，
无需单独委派控制。

## 6. 拦截期

### 6.1 判定流程（单体与网关同一套）

```
请求 → TokenContextFilter（单体）/ AuthenticationSaInterceptor（网关）
 1. ignore 名单（anyone/anyUser，现有 IgnoreProperties）  → 放行
 2. 全局开关 authEnabled = false                          → 放行
 3. 前缀归一化：/api/console/organization/user/page
              → /organization/user/page（裸路径，见 6.2）
 4. 裸路径+method 匹配「全量已配置接口集」（缓存A）
    ├─ 未命中（接口未纳管）→ notConfigUriAllow ? 放行 : 拒绝
    └─ 命中（接口已纳管）
 5. 加载「当前用户放行接口集」（缓存B，按 userId）
    加载器：用户 → 启用角色
           ├─ 含 OPERATIONS_ADMIN（运营者）→ 豁免，直接放行（短路）
           └─ 否则 → mdc_role_resource_rel → mdc_resource_api
                    （按 resource_id 匹配，授权表 resource_type 列为空，
                     id 统一菜单表 id 空间）→ uri+method 并集
    ├─ 用户集中存在 pattern：method 匹配(含ALL) 且 AntPathMatcher 命中 → 放行
    └─ 否则 → 拒绝，R.fail("无权限访问该接口：{uri}")
```

- 第 4 步决定"要不要管"，第 5 步决定"有没有权"。用户放行集 ⊆ 已配置集。
- 精确 uri 走 HashMap 快路径，通配 pattern 走列表遍历（量级几百，微秒级）。

### 6.2 前缀归一化规则

- **入库**：扫描/手录统一为裸路径（`/organization/user/page`）。
- **拦截**：请求路径剥掉「网关前缀 + 第一段服务前缀」后匹配。服务前缀集合
  （console/workbench/open 等）放配置（`IgnoreProperties` 扩展），不硬编码；
  单体版路径形态实现时按实况校验，保证两处逻辑一致。

### 6.3 缓存模型与失效（md-cache-key 新增两个 key）

| 缓存 | 键 | 内容 | 失效时机 |
|---|---|---|---|
| A 全量已配置接口 | 单 key | distinct(uri, method) | 配置变更（save/bind/delete/级联删） |
| B 用户放行集 | userId | Set\<uri+method\> + 运营者豁免标记 | ①配置变更：引用该资源的角色→角色下用户逐个失效；②授权变更（role_resource_rel 保存）：该角色下用户逐个失效；③用户角色变更：失效该用户 |

配置/授权均为低频操作，逐个失效可接受；TTL 24h 兜底。

### 6.4 模块划分（与数据权限架构对称）

```
mdp-base（纯逻辑，无 servlet/webflux 依赖）
└─ ApiPerm 判定引擎：匹配算法 + Provider SPI 接口

md-common-config（单体）              inner-gateway-server（微服务）
└─ Provider 实现                       └─ Provider 实现
   （CacheOps + Db 直查，               （CacheOps + Db 直查，网关自治，
    写操作负责失效）                     与 console 共享 Redis key）
└─ TokenContextFilter.auth 调用         └─ AuthenticationSaInterceptor 调用
```

### 6.5 错误响应

拒绝时返回 `R.fail("无权限访问该接口：{uri}")`（HTTP 200 + 业务码，前端统一弹提示）。
日志记 warn（用户、uri、method），便于排查"为什么被拦"。

## 7. 边界与错误处理

| 场景 | 行为 |
|---|---|
| 未登录请求 | 现有 token 逻辑先行拦截，接口权限只判定已登录用户 |
| worker / MQ / 定时任务 | 不经 web 拦截器，天然不受影响 |
| md-api 开放接口（SDK 调用） | 走 sop 网关，不在本次拦截范围 |
| 请求命中多个已配置 pattern | 任一命中即纳管；用户持有其中任一 pattern 即放行（并集） |
| pattern 的 method=ALL | 匹配任意请求方法 |
| 菜单/按钮被删除 | 级联删 `mdc_resource_api` 行 + 失效缓存 A/B |
| 新接口配置到已授权菜单 | 缓存失效后自动放行，无需重新授权 |
| 运营者（绑定启用中 OPERATIONS_ADMIN 角色） | **豁免一切接口权限**，加载器短路；角色变更经缓存B失效即时生效 |
| 其他内置角色（总公司/开发者管理员） | 不做硬豁免，与菜单授权保持一致 |

## 8. 测试策略（TDD）

- **引擎纯单测**（不启 Spring，md-base）：
  - AntPathMatcher 匹配：精确、尾缀 `/**`、中段 `*`、`?`、method=ALL
  - 纳管判定：命中/未命中 → 放行/拒绝/两种默认行为开关
  - 放行判定：用户集命中/未命中、多 pattern 并集、运营者豁免短路
  - 前缀归一化：带前缀路径 → 裸路径
- **服务层单测**（console-service）：
  - save/bind 的 uk 去重与幂等（重复选择不报错、不产生重复行）
  - delete 删行；菜单/按钮删除的级联删
  - 缓存失效：配置变更失效 A + 受影响用户 B；授权变更失效角色下用户 B
- **加载器单测**：用户→角色→资源→接口的多跳并集（含角色停用剔除、运营者标记）
