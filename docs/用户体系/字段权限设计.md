# 字段权限设计

> 版本：V1.0（2026-10-02）
> 定位：在菜单/按钮权限、接口权限、数据权限之后，补齐"字段级"权限维度，覆盖 配置 → 授权 → 鉴权 全链路。

## 1. 背景与目标

### 1.1 为什么不直接用 MyBatis-Flex 原生三件套

| 机制 | 原理 | 对本项目的局限 |
|---|---|---|
| 脱敏 `@ColumnMask` | 实体字段静态注解，结果集 set 值时执行 MaskManager 规则 | 静态全局，无法按 人/角色/页面 区分；`skipMask()` 靠 ThreadLocal 逃逸，脆弱 |
| 字段权限 `@Table(onSet=SetListener)` | MyBatis 给实体 set 值时逐字段回调，无权限置 null | 实体级一刀切：同一实体的所有查询走同一监听，**无法区分是哪个菜单页面发起的查询**；每行每字段回调有性能损耗；只作用于实体，VO 拷贝后管不到 |
| 字段加密 `onSet` | 同上，set 时加密 value | 与权限是正交问题（存储层保护），不混入本方案 |

核心缺陷：三者都锚定在"实体"上，而业务的字段权限是 **菜单（页面）× 角色 × 字段** 的三维关系。

### 1.2 目标

- 菜单上可配置受控字段（隐藏 / 脱敏 + 规则），即 `mdc_resource_field` 表（脚手架已生成）
- 角色管理按菜单树做字段授权，**拒绝模型**：受控字段默认全员可见，角色勾选的是"受限清单"
- 鉴权落在响应层（ResponseBodyAdvice）：按当前请求 URI 反查菜单，套用当前用户的字段规则
- 复用接口权限已验证的范式：SPI + Redis 用户权限缓存 + 授权变更失效链路
- 脱敏规则复用 MaskManager 内置 9 种（手机号/身份证/姓名/地址等）+ 自定义注册

### 1.3 关键依赖：`mdc_resource_api` 的 URI ↔ 菜单绑定

字段权限挂在菜单上，而鉴权发生在一次 HTTP 请求上。桥接靠已有的 `mdc_resource_api`：

```
请求 URI ──mdc_resource_api──► 资源ID(菜单/按钮) ──沿上级链──► 配置了字段规则的菜单 menuId
                                                                 │
当前用户角色 ──mdc_role_field_rel──► 受限字段集 ◄──mdc_resource_field(menuId)
```

## 2. 核心概念与决策

| 决策点 | 结论 |
|---|---|
| 授权语义 | **拒绝模型**：字段配置为受控后默认所有人可见；角色勾选 = 该角色对此字段 隐藏/脱敏。新增受控字段无需给存量角色补授权；运营管理员（`OPERATIONS_ADMIN`）天然豁免 |
| 字段挂靠 | `mdc_resource_field.menu_id` → `mdc_resource_menu`，任何菜单节点（目录/菜单/按钮）均可配置 |
| 鉴权执行点 | 响应层 `ResponseBodyAdvice`，JSON 写出前处理返回对象树 |
| 规则类型 | `10-隐藏`（置 null）、`20-脱敏`（按 mask_rule 规则变形）；`30-加密` 预留不实现 |
| 授权存储 | 新表 `mdc_role_field_rel(role_id, field_id)`，不复用 `mdc_role_resource_rel`（避免 field_id 与菜单 id 混用污染接口权限查询与资源回显） |

## 3. 表设计

### 3.1 修正 `mdc_resource_field`（字段规则配置）

现有问题：唯一键 `uk_resource_code(property)` 是 property 全局唯一——`phone` 全系统只能配一次，明显错误。

```sql
ALTER TABLE `mdc_resource_field` DROP INDEX `uk_resource_code`;
ALTER TABLE `mdc_resource_field`
  ADD COLUMN `rule_type` tinyint NOT NULL DEFAULT 10 COMMENT '处理动作 [10-隐藏 20-脱敏]' AFTER `name`,
  ADD COLUMN `mask_rule` varchar(64) DEFAULT NULL COMMENT '脱敏规则(rule_type=20时必填)，取 MaskManager 注册名' AFTER `rule_type`,
  ADD UNIQUE KEY `uk_menu_property` (`menu_id`, `property`);
```

字段说明：

| 列 | 含义 |
|---|---|
| menu_id | 所属菜单 |
| property | 受控字段名（VO 的 Java 属性名，如 `phone`） |
| name | 展示名（授权树上显示，如"手机号"） |
| rule_type | 10-隐藏（无权限置 null）；20-脱敏（无权限按规则变形） |
| mask_rule | 脱敏规则名，对应 MaskManager 注册名（内置：MOBILE/CHINESE_NAME/ID_CARD/EMAIL/BANK_CARD/ADDRESS/PASSWORD/CAR_LICENSE/FIXED_PHONE + 自定义） |
| state | 启用才参与鉴权 |

### 3.2 新增 `mdc_role_field_rel`（角色-字段受限关系）

```sql
CREATE TABLE `mdc_role_field_rel` (
  `id` bigint NOT NULL COMMENT 'ID',
  `role_id` bigint NOT NULL COMMENT '角色ID',
  `field_id` bigint NOT NULL COMMENT '字段规则ID(mdc_resource_field.id)',
  `created_by` bigint DEFAULT NULL COMMENT '创建人id',
  `created_at` datetime(3) NOT NULL COMMENT '创建时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_role_field` (`role_id`, `field_id`),
  KEY `idx_field_id` (`field_id`)
) COMMENT='角色字段受限关系（拒绝模型：存在的行=该角色对该字段受限）';
```

不用逻辑删除：授权保存走"整棵菜单树差异重写"（与 `saveRoleResource` 同款）。

## 4. 配置（菜单管理）

- 菜单管理详情新增 **「字段配置」标签页**，复用已生成的 `ResourceFieldController`（`/permission/resourceField/*`）CRUD，按 `menuId` 过滤
- 录入校验（Service 层，fail fast）：
  - `rule_type=20` 时 `mask_rule` 必填且必须是 MaskManager 已注册名（启动时把注册名单暴露给配置页下拉）
  - 同菜单下 `property` 重复直接报错（DB 唯一键兜底）
  - `property` 仅允许 `[a-zA-Z][a-zA-Z0-9_]*`，防注入与乱配
- 配置变更（增/删/改/启停）→ 失效**所有用户**的字段权限缓存（低频操作，全量失效可接受，同接口权限缓存C的思路）

## 5. 授权（角色管理）

### 5.1 交互

- 角色管理「资源授权」的菜单树上，受控字段作为**叶子节点**挂在所属菜单下（前端展示类型：`60-字段`，图标区分）
- 勾选语义 = **受限**（与菜单勾选"拥有"相反），UI 上用红色/禁止图标明示，避免管理员惯性误操作
- 勾选父菜单不联动勾选字段节点（字段节点独立勾选）

### 5.2 接口与保存

- 查询：`GET /permission/role/{roleId}/field` → 返回该角色已受限的 fieldId 集合
- 保存：`POST /permission/role/saveRoleField`，入参 `{roleId, fieldIdList}`，实现同 `saveRoleResource`：按 roleId 全量删旧插新 + 事务
- 失效：保存后按 `invalidateUserResourceApiCacheByRoleIds` 同款链路，查出该角色下所有用户，批量删除其字段权限缓存

## 6. 鉴权（响应层）

### 6.1 运行时流程

```
Controller 返回 R<Page<UserVo>>
        │
FieldPermAdvice(ResponseBodyAdvice.beforeBodyWrite)
        │ 1) 未登录 / 无 HTTP 上下文 → 直接放行
        │ 2) URI 归一化（剥网关前缀+服务前缀，与 ApiPermChecker 同一套归一化）
        │ 3) URI → resource_api → resourceId → 沿菜单上级链找"最近一个有字段规则的菜单" menuId
        │    （URI→menuId 映射做进程内缓存，配置变更时随缓存C一起清）
        │ 4) UserFieldPerm 缓存取当前用户规则：menuId → {property: rule}
        │    运营管理员豁免；无规则 → 放行
        │ 5) FieldPermEngine.apply(body, rules)
        │    遍历 R → data → Page.records / List / 单对象 的对象树，
        │    命中 property：rule_type=10 → set null；20 → MaskManager 规则变形
        │ 6) 写回响应
```

### 6.2 组件划分

| 组件 | 位置 | 职责 |
|---|---|---|
| `UserFieldPerm` | md-core（apiperm 同包风格） | 缓存模型：`boolean operationsAdmin` + `Map<Long, Map<String, FieldRule>>`；**必须保留无参构造**（Redis Jackson 反序列化，UserApiPerm 踩过的坑） |
| `FieldPermProvider`（SPI） | md-core | `findUserPerm(userId)`、`findMenuFieldRules()`（全量配置，缓存C） |
| `FieldPermProviderImpl` | md-public（与 ApiPermProviderImpl 同模块 md-resource-api 或独立 md-resource-field） | 查 `mdc_user_role_rel` → `mdc_role_field_rel` → `mdc_resource_field` 组装用户受限集；`OPERATIONS_ADMIN` 短路 |
| `FieldPermEngine` | md-core | 纯函数 `apply(Object target, Map<String, FieldRule> rules)`：对象树遍历 + 置空/脱敏。导出等非 JSON 通道手动调同一引擎。脱敏经可插拔 `Masker`：md-core 内置 `BuiltinMasker`（9 规则与 mybatis-flex `Masks` 同名同算法），Advice 层优先委托 `MaskManager`（业务自定义注册生效），未注册回退内置 |
| 开关 | md-common-pojo | `mdp.ignore.field-auth-enabled`（默认 true），关闭则全员看字段原文，用于灰度 |
| `FieldPermAdvice` | md-mvc-flex（advice 包，与 UpdateFieldAdvice 同处） | ResponseBodyAdvice 入口，负责 URI→menuId 解析与缓存读取，委托 Engine |
| `UserResourceFieldCacheKeyBuilder` 等 | md-cache-key | 用户缓存B / 全量配置缓存C 的 key |

### 6.3 对象树遍历规则（Engine）

- 入口类型识别：`R` → 取 `data`；`Page` → 取 `records`；`Collection`/`数组` → 逐元素；Map → 逐 value；其余按 bean 处理
- bean 遍历：按 `rules` 的 property 名查 `PropertyDescriptor`（缓存 `Class → PropertyDescriptor[]`，与 UpdateFieldAdvice 的 `propertyDescriptorMap` 同法），命中即有写方法则置 null / 脱敏后回写
- 嵌套递归：对 bean 的非简单类型字段递归下钻，**深度上限 5 层**，循环引用用 `IdentityHashMap` 已访问集合截断
- 同名字段语义：对象树中**所有**名为 `phone` 的字段都受限（含嵌套 VO）——这是特性而非误伤：同一页面里"手机号"就该统一脱敏；若某嵌套对象确需放行，配置时用更具体的字段设计规避
- 脱敏仅处理 `String` 类型字段；`rule_type=10` 对任意类型置 null
- 性能兜底：单请求对象数超过阈值（默认 5000，配置项）时记 warn 日志并截断遍历，防大导出 OOM/超时

### 6.4 不适用的通道（明确边界）

- **Excel 导出 / 文件下载**：不走 ResponseBodyAdvice，导出服务组装完数据后手动 `FieldPermEngine.apply()`（在导出基类里统一加钩子）
- **内部调用**（定时任务、worker-server、服务间调用）：无登录上下文直接放行——内部通道默认可信，与接口权限 `StpUtil.isLogin()` 判空放行一致
- **网关**：字段鉴权只在业务服务内做，网关不参与（网关无业务对象模型）

## 7. 前端配合

- 新增 `GET /permission/resourceField/current?menuId=`：返回当前用户在该菜单的受限字段及规则，前端进入页面时拉取
- 列表页（vxe-table）：受限列动态隐藏（rule_type=10）或单元格渲染脱敏占位（后端已脱敏时直接展示）
- 详情/编辑页：字段隐藏时对应表单项不渲染；脱敏字段只读展示
- 编辑回显防覆盖：编辑回显的数据已经过服务端字段权限处理（隐藏=null、脱敏=变形值），原样提交会覆盖真实数据——后端 `updateDtoById` 已有"按提交字段更新"语义，前端提交时剔除受限字段：**隐藏字段无条件剔除**（null 会置空真实值）；**脱敏字段值与回显一致（未修改）才剔除**，输入新值正常提交（`utils/fieldPerm.ts` 的 `stripRestricted`，用户管理页已示范接入）

## 8. 缓存与失效

| 缓存 | key | 内容 | 失效时机 |
|---|---|---|---|
| 用户受限集（缓存B） | `user_field_perm:{userId}` | `UserFieldPerm` | 角色字段授权保存/删除；用户角色变更；角色启停（复用现有角色变更失效链路扩展） |
| 全量字段配置（缓存C） | `resource_field:all` | `mdc_resource_field` 全量启用规则（menuId→rules） | 字段配置增删改/启停（全量失效B+C） |
| URI→menuId 映射 | 进程内 `ConcurrentHashMap` | URI+method → menuId | 随缓存C失效一并清 |

缓存B 组装（ProviderImpl）：

```
userId → mdc_user_role_rel(启用角色)
       → 含 OPERATIONS_ADMIN → operationsAdmin=true 短路
       → mdc_role_field_rel(fieldIds) join mdc_resource_field(state=1)
       → 按 menuId 分组：Map<menuId, Map<property, FieldRule>>
```

## 9. 与字段加密的关系（后续演进）

字段加密是存储层保护（落库密文），与本方案正交，本期不实现，仅预留：

- `rule_type=30-加密` 枚举位预留
- 演进路径：写入时加密（Service 层或 mybatis-flex 类型处理器）+ 读取时按角色解密（复用本方案的 menuId→角色判定，在 Engine 里加解密动作）
- 注意加密字段不可做模糊查询/排序，选型时需按字段评估（如手机号加密后无法 LIKE，需要盲索引等配套）

## 10. 实施拆解

1. **DDL**：修正 `mdc_resource_field` 唯一键 + 加 `rule_type`/`mask_rule` 列；新建 `mdc_role_field_rel`
2. **console-pojo**：`ResourceField` 实体/VO/DTO 补新列；新建 `RoleFieldRel` 实体（含 Base）
3. **md-core**：`UserFieldPerm`、`FieldRule`、`FieldPermProvider` SPI、`FieldPermEngine` + 单测（TDD：对象树遍历/嵌套/循环引用/深度截断/隐藏/脱敏）
4. **md-public**：`FieldPermProviderImpl` + 缓存 key + 失效链路（接入现有 `invalidateUserResourceApiCacheByRoleIds` 同批失效）
5. **md-mvc-flex**：`FieldPermAdvice` + 单测（URI→menuId 解析、无登录放行、阈值截断）
6. **console-service/web**：角色字段授权接口（查询/保存）+ 配置校验；`ResourceFieldService` 录入校验
7. **导出通道**：导出基类接入 `FieldPermEngine`
8. **前端**：菜单管理「字段配置」tab；角色授权树字段叶子节点；页面列隐藏/脱敏渲染；编辑页脱敏值提交剔除
9. **菜单资源初始化**：`/permission/resourceField/*`、角色字段授权接口纳入 `mdc_resource_api`（参考 `resource-api-data-init.sql` 同款脚本）

## 11. 关键风险与对策

| 风险 | 对策 |
|---|---|
| 响应遍历性能 | PropertyDescriptor 缓存 + 对象数阈值截断 + 仅在有规则的 menuId 上才遍历（绝大多数请求零开销：一次 map 查空即返回） |
| 同名字段"误伤"嵌套对象 | 语义即如此（页面级统一），文档明示；特殊场景拆字段名 |
| 脱敏值被表单回写覆盖 | 前端提交剔除未修改的脱敏字段；后端可考虑对脱敏特征的提交值拒绝（兜底，二期） |
| 缓存不一致 | 失效链路复用已验证的角色变更链路；配置变更全量失效（低频） |
| 编辑接口（getById）挂在按钮上 | URI→resourceId 可能是按钮（menu_type=50），沿上级链找最近有字段规则的菜单，已在 6.1-3 覆盖 |
