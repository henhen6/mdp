# 接口调用链路 - 二次开发文档

> 面向读者：基于本项目进行二次开发的开发人员。阅读本文档后，您可以快速定位接口调用链路的问题、新增开放接口、扩展网关校验能力。

## 1. 链路总览

```
第三方 OpenClient
      │ HTTP POST /api
      ▼
IndexController#index ───────────── mdp-apps/md-gateway/sop-gateway-server/.../controller/IndexController.java:70
      │ paramExecutor.build(request) 解析参数 → ApiRequestContext
      ▼
RouteService#route ──────────────── .../service/impl/RouteServiceImpl.java:92
      │ sopValidator.validate() ① 参数与安全校验
      │ doPreRoute() ② 路由拦截器前置（token 有效性校验、调用日志）
      │ doRoute() ③ Dubbo 泛化调用 api-service 真实方法
      │ doAfterRoute() ④ 路由拦截器后置
      │ resultWrapper.wrap() ⑤ 包装为统一响应
      ▼
ParamExecutor#write 写回 HTTP 响应
```

### 模块职责

| 模块 | 职责 |
| --- | --- |
| `mdp-sdk/mdp-sdk-core` | 第三方调用工具：`OpenClient` 组装公共参数、RSA2 签名、HTTP 请求、响应解析 |
| `mdp-sdk/mdp-simple-sdk` | 封装 api-service 中所有 `@Open` 接口为 `XxxApi` 请求对象 |
| `mdp-apps/md-gateway/sop-gateway-server` | 统一入口、校验、路由转发、调用日志 |
| `mdp-apps/md-api/api-service` | 真实业务实现，接口方法需标注 `@Open` |
| `mdp-base/md-sop-support` | 开放平台基础能力：`@Open` 注解、接口注册、AES 加解密（`MdpBizMsgCrypt`） |

## 3. 校验流程详解（ApiValidator#validate）

`ApiValidator#validate`（`ApiValidator.java:81`）按以下顺序执行，任一失败即抛出 `ApiException`：

| 步骤 | 方法 | 校验内容 |
| --- | --- | --- |
| 1 | `checkApiInfo` | method+version 能否路由到接口（`ApiManager` 缓存自 `mdo_api` 表）、接口是否启用 |
| 2 | `checkField` | 公共参数完整性：appKey/method/version/charset/timestamp 必填；`signType`/`sign` 仅在接口 `needSign=true` 时必填 |
| 3 | `checkApp` | appKey 对应应用存在、未禁用、在有效期内 |
| 4 | `checkPermission` | 接口 `permission=true` 时校验应用是否被授权 |
| 5 | `checkSign` | 接口 `needSign=true` 时用 `publicKeyApp` 做 RSA2 验签（`PlatformSigner`） |
| 6 | `checkTimeout` | timestamp 是否超过 `mdp.gateway.timeout-seconds`（0 表示不校验） |
| 7 | `checkFormat` | format 参数合法性 |
| 8 | `checkIP` | IP 黑名单拦截 |
| 9 | `checkUploadFile` | 上传文件的单文件/总大小限制 |
| 10 | `checkToken` | 接口 `needToken=true` 时校验 accessToken 非空（**只查非空**，真实有效性在拦截器阶段） |

`validate` 通过后，`RouteServiceImpl#doPreRoute` 执行 `RouteInterceptor` 链，其中 `TokenValidateInterceptor`（`match` 条件为 `needToken=true`）通过 `AppManager#getAppIdByAccessToken(appKey, token)` 从 Redis 校验 `{appKey}:{token}` 映射是否存在——复合 key 设计防止 A 应用 token 冒充 B 应用。

> RESTful 入口（`validateRest`，`ApiValidator.java:108`）校验项较少：接口存在且为 RESTFUL 模式、应用、IP、上传文件、token，**不做签名校验**。

## 4. 接口注册机制

`@Open` 注解接口如何被网关感知：

1. api-service 启动时，`md-sop-support` 扫描容器中标注 `@Open` 的方法（含 `value`、`version`、`permission`、`needToken`、`needSign`、`hasCommonResponse` 属性）；
2. 通过 Dubbo 调用网关的 `ApiRegisterServiceImpl#register`，将接口元数据写入 `mdo_api` 表（已存在时校验应用归属，防止接口名冲突；网关不可用时每 5 秒重试）；
3. 网关的 `ApiManager` 从库中加载接口信息（含 `paramInfo` 参数签名元数据）用于路由与校验。

## 5. 如何新增一个开放接口

以新增"根据编码查询组织"为例：

**第一步**：在 `mdp-apps/md-api/api-service` 定义接口并标注 `@Open`：

```java
// top/mddata/api/OrgOpenService.java
@Open(value = "org.getByCode")           // 版本默认 1.0
OrgResp getByCode(OrgQuery query);
```

**第二步**：在 `api-service` 的 `impl` 中实现（类需标注 `@DubboService` 供网关泛化调用），方法签名中的 `OpenContext` 参数由网关自动注入：

```java
@Override
public OrgResp getByCode(OrgQuery query) {
    // 可通过 OpenContext.current() 拿到 appId/appKey/callLogId/clientIp 等上下文
    ...
}
```

**第三步**：在 `mdp-sdk/mdp-simple-sdk` 中补充对应的 `XxxApi`（继承 `BaseParam`，实现 `method()` 返回 `"org.getByCode"`）、请求 DTO、响应 Resp，供第三方调用。

**第四步**：重启 api-service，接口自动注册到网关；确认 `mdo_api` 表中出现记录且 `state` 为启用。

注意事项：

- `needToken` 默认 `true`：调用方需携带 accessToken；
- `needSign` 默认 `false`：设为 `true` 时调用方必须用应用私钥签名（适合安全敏感接口）；
- `permission=true` 时需在管理端为应用授权后才能调用；
- `hasCommonResponse=false` 时网关只返回 data 部分；
- 接口名（method）全局唯一，重复注册会报"已存在于其他应用中"。

### 5.1 needToken / needSign 选型指南

两个属性解决的是不同层面的安全问题，选型时先理解校验的是什么：

| 属性 | 校验内容 | 防范的风险 | 验证成本 |
| --- | --- | --- | --- |
| `needToken`（默认 true） | accessToken 有效（Redis 中 `{appKey}:{token}` 映射存在且未过期） | 未授权应用冒充已授权应用、token 失效后继续访问 | 极低（一次 Redis 查询） |
| `needSign`（默认 false） | 请求参数整体未被篡改（应用私钥签名，平台公钥验签） | 参数被中间人篡改（如改金额、改目标 id）、请求抵赖 | 较高（每次 RSA 运算 + 调用方需上传密钥并保管私钥） |

#### 什么接口适合必须校验签名（needSign=true）

- **传输应用级凭证的接口**：如 `accessToken.get`——请求中含 `appSecret`，且是"换取通行证"的入口，被篡改后果严重（典型组合：`needToken=false, needSign=true`，否则出现"要 token 才能换 token"的死循环）；
- **不可逆的写操作且影响面大的接口**：资金类（划拨、退款）、主数据删除、权限变更——参数一旦被篡改无法回滚；
- **参数敏感但无其他加密保护的接口**：请求经过不受控的网络链路（跨公网）且参数本身含敏感数据。

#### 什么接口适合不校验签名（needSign=false）

- **常规查询/分页接口**：如 `user.page`、`org.getById`——只读、无篡改收益，token 校验已足够确认调用方身份；
- **高频接口**：每次 RSA 验签的计算开销在高 QPS 下不可忽略，非必要不开；
- **有 HTTPS 传输加密保障、且调用方是内部可信应用**的接口——签名防篡改的边际收益低，而密钥分发（公钥上传、私钥保管）的运维成本是实实在在的。

#### 什么接口适合携带 accessToken（needToken=true，默认值）

绝大多数业务接口都应保持默认。`needToken=true` 意味着：调用前必须先走 `accessToken.get` 换取令牌，平台由此能识别"是哪个应用在调用"并施加会话级控制（过期、失效、跨应用隔离）。适合：

- 所有返回业务数据、执行业务操作的接口（`org.save`、`user.page`、`msg.sendSms` 等）。

#### 什么接口适合不携带 accessToken（needToken=false）

- **引导类/引导前置接口**：`accessToken.get` 本身——它就是发放 token 的接口，逻辑上不可能要求先有 token（用 `needSign=true` 补充安全性）；
- **无状态的健康检查、探活类接口**：不返回业务数据，只证明 api-service 存活；
- **完全公开的静态数据接口**：如公告、字典等所有应用可见且无敏感性的数据（此时建议评估是否还需要走开放网关）。

#### 选型速查表

| 接口类型 | needToken | needSign | 典型例子 |
| --- | --- | --- | --- |
| 换取令牌的引导接口 | false | true | `accessToken.get` |
| 常规只读查询 | true | false | `user.page`、`org.getById` |
| 常规写操作 | true | false | `org.save`、`user.updateById` |
| 高敏感写操作（资金/删除/权限） | true | true | 退款、删除主数据 |
| 健康检查/公开静态数据 | false | false | 探活接口 |

> 经验法则：先想清楚该接口"被冒用"与"被篡改"各自的最坏后果——冒用靠 token 挡、篡改靠签名挡；两者后果都轻的（只读、公开）可以都不设防，后果严重的逐级加码。不要为了"看起来安全"一律开 needSign——调用方密钥管理成本和网关验签开销都是真实的代价。

## 6. 扩展点

| 需求 | 扩展方式 |
| --- | --- |
| 新增校验规则 | 实现 `SopValidator` 替换/增强 `ApiValidator`，或实现 `RouteInterceptor` 挂入拦截器链（`getOrder` 控制顺序） |
| 更换签名算法 | 实现 `Signer` 接口替换 `PlatformSigner`（SDK 端同步修改 `SignUtil`） |
| 修改响应包装 | 实现 `ResultWrapper` |
| 修改请求/响应序列化 | 实现 `Serde` |
| 调整网关入口路径/超时 | 配置 `mdp.gateway.path`、`mdp.gateway.rest`、`mdp.gateway.timeout-seconds`、`mdp.gateway.timestamp-pattern` |
| 限制上传大小 | 配置 `mdp.upload.one-file-max-size`、`mdp.upload.total-file-max-size` |

## 7. 问题定位

### 7.1 日志关键字

| 日志 | 输出方 | 含义 |
| --- | --- | --- |
| `收到客户端请求, ip={}, apiRequest={}` | 网关 `RouteServiceImpl` | 请求已进入路由，可查看完整请求参数 |
| `接口请求报错` | 网关 `RouteServiceImpl` | 校验或调用异常，堆栈在同行日志 |
| `验签错误, code={}` | 网关 `PlatformSigner` | RSA2 验签异常明细 |
| `accessToken无效、已过期或与当前应用不匹配` | 网关 `TokenValidateInterceptor` | token 校验失败 |
| `注册开放接口` | 网关 `ApiRegisterServiceImpl` | 接口元数据注册 |

### 7.2 调用日志

网关在 `finally` 中发布 `CallLogEvent` 将 `ApiCallLog` 异步落库（含请求参数、响应、耗时、执行状态），可用于对账与排障。业务侧可通过 `OpenContext#getCallLogId()` 将业务数据与调用日志关联（接口回调链路即依赖此 ID）。

### 7.3 常见问题速查

| 现象 | 排查 |
| --- | --- |
| ISV_INVALID_METHOD | `mdo_api` 表无记录（api-service 未启动/注册失败）或 state 未启用 |
| ISV_INVALID_SIGNATURE | 调用方私钥与平台 `publicKeyApp` 不配对；待签名内容包含 sign 参数或未排序 |
| AOP_INVALID_AUTH_TOKEN | Redis 中 `{appKey}:{token}` 不存在：token 过期、跨应用使用、或 Redis 数据丢失 |
| ISV_INVALID_TIMESTAMP | 调用方时间偏差超过 `timeout-seconds` |
| 请求到不了业务实现 | 检查 Dubbo 泛化调用目标：`mdo_api.param_info` 中的接口类名/方法名/参数类型与实际是否一致（方法签名变更后需同步重注册） |
