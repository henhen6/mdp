# 接口调用链路 - 接入说明文档

> 面向读者：第三方应用开发者。阅读本文档后，您可以了解如何申请接入、如何获取访问令牌、如何通过 SDK 或 HTTP 调用平台的开放接口，以及如何处理请求签名。

## 1. 链路概述

第三方应用调用平台开放接口的整体链路如下：

```
                                ┌ MDP 平台 ────────────────────────────────────────────┐
                                │ ┌─────────────────────┐        ┌────────────────┐   │
┌──────────────┐                │ │  sop-gateway-server │  Dubbo │  api-service   │   │
│ OpenClient   │   HTTP POST    │ │  参数校验/验签/token   │ ─────> │  真实业务方法    │   │
│ (SDK/HTTP)   │ ─────────────> │ │  结果包装/调用日志     │ <───── │  (@Open 标记)   │   │
│              │   /api 入口     │ └─────────────────────┘  泛化调用 └────────────────┘   │
│              │ <───────────── │                                                      │
└──────────────┘   JSON 响应     └──────────────────────────────────────────────────────┘
```

要点：

- 所有开放接口统一由网关 `sop-gateway-server` 的 `/api` 入口承接（`IndexController#index`），**第三方应用不直接访问 api-service**。
- 网关完成权限检查、签名验证、IP 拦截、token 校验（详见 `ApiValidator#validate`）后，通过 Dubbo 泛化调用转发到 api-service 中真实的业务方法。
- api-service 中所有标记了 `@com.gitee.sop.support.annotation.Open` 注解的接口方法，才是对第三方开放的接口。

## 2. 接入前准备

### 2.1 创建应用并获取凭证

在开放平台控制台创建应用后，您将获得：

| 参数 | 说明 | 用途 |
| --- | --- | --- |
| `appKey` | 平台分配给您的应用ID | 每次请求必传 |
| `appSecret` | 应用密钥 | 换取 accessToken 使用，**请妥善保管，切勿外泄** |

### 2.2 上传应用公钥（RSA2）

如果您需要调用**开启了签名校验**的接口（如 `accessToken.get`），需要：

1. 在本地生成 RSA2（SHA256WithRSA，建议 2048 位）密钥对；
2. 将**公钥**上传到平台（即平台侧 `AppKeys.publicKeyApp` 字段）；
3. **私钥**自己保留，用于对请求参数签名。

密钥对生成示例代码（使用 SDK 提供的 `RsaTool` 工具类，位于 `mdp-sdk-core` 的 `top.mddata.sdk.core.sign.RsaTool`）：

```java
import top.mddata.sdk.core.sign.RsaTool;

public class KeyPairDemo {
    public static void main(String[] args) throws Exception {
        // PKCS8 格式适用于 Java 端；密钥长度建议 2048 位
        RsaTool rsaTool = new RsaTool(RsaTool.KeyFormat.PKCS8, RsaTool.KeyLength.LENGTH_2048);
        RsaTool.KeyStore keyStore = rsaTool.createKeys();

        // 公钥：上传到平台（AppKeys.publicKeyApp），平台用它验证您的签名
        String publicKey = keyStore.getPublicKey();
        // 私钥：本地妥善保管，用于签名（即 OpenClient 构造方法的 privateKeyIsv 参数）
        String privateKey = keyStore.getPrivateKey();

        System.out.println("公钥：" + publicKey);
        System.out.println("私钥：" + privateKey);
    }
}
```

说明：

- `KeyFormat.PKCS8`（Java 适用）为默认推荐格式；若您的签名端为非 Java 技术栈，可改用 `KeyFormat.PKCS1`，生成后公钥仍上传平台，私钥在您的签名端使用；
- 不使用 SDK 时，也可用 OpenSSL 生成等价的 PKCS8 密钥对：

```bash
# 生成 2048 位 PKCS8 私钥
openssl genrsa -out private_key.pem 2048
openssl pkcs8 -topk8 -inform PEM -in private_key.pem -outform PEM -nocrypt -out private_key_pkcs8.pem
# 从私钥导出公钥
openssl rsa -in private_key_pkcs8.pem -pubout -out public_key.pem
```

> 公钥用于平台验证您的请求签名；私钥只在您手中，平台无法伪造您的请求。

### 2.3 获取访问令牌 accessToken

除 `accessToken.get` 等引导接口外，绝大多数接口要求请求中携带有效的 `accessToken`。获取方式：

调用 `accessToken.get` 接口（该接口本身**不需要 token，但需要签名**），使用 `appKey + appSecret` 换取：

- 若已有未过期的 token，平台直接返回（除非传 `forceRefresh=true`）；
- 否则生成新 token 并缓存，默认有效期 2 小时。

`accessToken` 与 `appKey` 绑定校验，A 应用的 token 不能用于 B 应用。

## 3. 请求规范

### 3.1 请求入口

```
POST {网关地址}/api
Content-Type: application/x-www-form-urlencoded（文件上传使用 multipart/form-data）
```

网关也提供 RESTful 风格入口：`{网关地址}/rest/{method}?v=1.0`，仅适用于标记为 RESTFUL 模式的接口。

### 3.2 公共请求参数

| 参数 | 类型 | 是否必填 | 最大长度 | 说明 | 示例 |
| --- | --- | --- | --- | --- | --- |
| appKey | String | 是 | 32 | 平台分配给开发者的应用 ID | 2014072300007148 |
| method | String | 是 | 128 | 接口名称 | user.page |
| version | String | 是 | 3 | 接口版本，固定为：1.0 | 1.0 |
| format | String | 否 | 40 | 仅支持 JSON | JSON |
| charset | String | 是 | 10 | 请求编码格式 | utf-8 |
| signType | String | 视接口配置 | 10 | 签名算法类型，支持 RSA2 和 RSA，推荐 RSA2。仅接口要求签名（needSign=true）时必填 | RSA2 |
| sign | String | 视接口配置 | 344 | 请求参数的签名串。仅接口要求签名（needSign=true）时必填 | 详见签名 |
| timestamp | String | 是 | 19 | 发送请求的时间，格式 `yyyy-MM-dd HH:mm:ss`，超时请求会被拒绝 | 2026-07-24 03:07:50 |
| accessToken | String | 视接口配置 | 512 | 访问令牌，通过 accessToken.get 接口获取。仅接口要求令牌（needToken=true）时必填 | 详见示例 |
| bizContent | String | 是 | 不限 | 业务参数集合，除公共参数外所有请求参数均放在此参数中传递 | `{"name":"张三"}` |
| notifyUrl | String | 否 | - | 回调地址。若接口需要异步回调结果，传入此参数（详见《接口回调链路 - 说明文档》） | https://xxx/notify |

> 注意：`signType`、`sign`、`accessToken` 是否必填，取决于目标接口在平台侧的 `needSign`、`needToken` 配置。默认情况下：需要 token（大多数接口）、不需要签名。具体以各接口文档为准。

### 3.3 请求签名（RSA2）

仅当接口要求签名时需要执行以下步骤：

1. 将所有请求参数（**不含 `sign` 本身**）按参数名 ASCII 码升序排序；
2. 组成 `key=value` 并用 `&` 连接，得到待签名内容；
3. 使用您的**应用私钥**对待签名内容进行 SHA256WithRSA（RSA2）签名；
4. 签名结果放入 `sign` 参数。

平台收到请求后，使用您上传的公钥（`publicKeyApp`）以相同规则验签。

### 3.4 响应格式

```json
{
    "code": "0",
    "msg": "",
    "subCode": "",
    "subMsg": "",
    "data": {
        "id": 1,
        "name": "Jim"
    }
}
```

- `code` 为 `"0"` 表示成功，其余为失败；
- 失败时 `subCode` / `subMsg` 携带具体错误信息；
- 个别接口若声明了 `hasCommonResponse=false`，则只返回 `data` 部分的内容。

### 3.5 常见错误码

| 错误 | 说明 | 排查建议 |
| --- | --- | --- |
| ISV_INVALID_METHOD | 接口不存在或未启用 | 检查 method/version 是否正确 |
| ISV_MISSING_APP_KEY / ISV_INVALID_APP_KEY | appKey 缺失或不合法 | 核对 appKey |
| ISV_MISSING_SIGNATURE / ISV_INVALID_SIGNATURE | 签名缺失或错误 | 核对私钥与平台公钥是否配对、签名内容是否包含多余参数 |
| ISV_INVALID_TIMESTAMP | 请求超时 | 检查服务器时间，timestamp 超过网关配置的超时秒数会被拒绝 |
| AOP_INVALID_AUTH_TOKEN | accessToken 缺失或无效 | 先调用 accessToken.get；检查 token 是否过期、是否与 appKey 匹配 |
| ISV_IP_FORBIDDEN | IP 被禁止访问 | 联系平台管理员检查 IP 黑白名单 |
| ISV_ROUTE_NO_PERMISSIONS | 无接口授权 | 联系平台管理员为应用授权该接口 |

## 4. 使用官方 SDK 调用（推荐）

平台提供 `mdp-sdk`（Maven 依赖），封装了参数组装、签名、请求、响应解析的全部细节：

- `mdp-sdk-core`：核心工具类，提供 `OpenClient` 请求客户端；
- `mdp-simple-sdk`：封装了所有 `@Open` 接口，每个接口一个 `XxxApi` 类。

### 4.1 初始化客户端

```java
// url：网关地址；appKey：平台分配；privateKeyIsv：您的应用私钥（RSA2 签名用）
OpenClient client = new OpenClient("https://gateway.xxx.com/api", "您的appKey", "您的应用私钥");
```

`OpenClient` 线程安全，声明一个即可复用。可选通过 `OpenConfig` 自定义超时时间、签名开关等：

```java
OpenConfig config = new OpenConfig()
        .setConnectTimeoutSeconds(10)
        .setReadTimeoutSeconds(10);
OpenClient client = new OpenClient(url, appKey, privateKey, config);
```

### 4.2 获取访问令牌

```java
AccessTokenGetDto dto = new AccessTokenGetDto();
dto.setAppKey("应用ID").setAppSecret("应用秘钥");

// 该接口需要签名，AccessTokenGetApi 中已声明 signEnabled=true
Result<AccessTokenGetResp> result = client.execute(new AccessTokenGetApi().setBizModel(dto));
if ("0".equals(result.getCode())) {
    // 后续请求自动/手动携带 accessToken
    String accessToken = result.getData().getAccessToken();
}
```

### 4.3 调用业务接口

```java

OrgPageApi param = new OrgPageApi();
OrgQuery query = new OrgQuery();
// ... 组装查询条件
param.setBizModel(query);


// 设置默认 accessToken 后，所有请求自动携带
client.setDefaultAccessToken(accessToken);
// 或者每次请求接口单独设置 accessToken
param.setAccessToken(accessToken);

Result<Page<OrgResp>> pageResult = client.execute(param);
```

说明：

- `OpenClient#execute` 会自动填充 `appKey`、`method`、`version`、`charset`、`timestamp` 等公共参数；
- 是否签名由「请求级 `BaseParam#getSignEnabled()`」优先决定，其次取全局 `OpenConfig#isSignEnabled()`（默认关闭）；
- 文件上传/下载使用 `DownloadAware` 相关请求对象，`execute` 会自动改走下载流。

## 5. 不使用 SDK 的 HTTP 调用

若您的技术栈无法引入 SDK，可直接 HTTP POST 表单到网关 `/api`：

```bash
curl -X POST 'https://gateway.xxx.com/api' \
  -d 'appKey=您的appKey' \
  -d 'method=user.page' \
  -d 'version=1.0' \
  -d 'format=JSON' \
  -d 'charset=utf-8' \
  -d 'timestamp=2026-07-24 03:07:50' \
  -d 'accessToken=您的token' \
  -d 'bizContent={"current":1,"size":10}'
```

若接口要求签名，还需按 3.3 节规则计算 `sign`、并携带 `signType=RSA2` 一并提交。

## 6. 接口列表

当前平台开放的接口（method 名即 `@Open` 注解的 value）：

| 分类 | method | 说明 |
| --- | --- | --- |
| 令牌 | accessToken.get | 获取访问令牌（needToken=false，needSign=true） |
| 组织机构 | org.save / org.updateById / org.getById / org.page | 组织机构增删改查 |
| 用户 | user.batchSave / user.updateById / user.getById / user.page | 用户增删改查 |
| 消息 | msg.sendSms / msg.sendEmail / msg.sendNotice | 短信、邮件、站内信发送 |

各接口的请求/响应字段以 `mdp-simple-sdk` 中对应的 `XxxApi` / `XxxDto` / `XxxResp` 类为准。

## 7. 常见问题

**Q1：请求返回"请求超时"？**
timestamp 与平台服务器时间差超过网关配置的超时秒数（`mdp.gateway.timeout-seconds`）会被拒绝，请校准服务器时间。

**Q2：签名总是验签失败？**
- 确认签名内容不包含 `sign` 参数本身；
- 确认参数按 ASCII 升序排序，值不做 URL 编码；
- 确认您用的是应用私钥签名，且平台存储的是对应公钥（`publicKeyApp`）。

**Q3：token 提示无效？**
- token 默认 2 小时有效，过期请重新获取；
- token 与 appKey 绑定，不能跨应用使用；
- `forceRefresh=true` 后旧 token 立即失效。

**Q4：调用成功但没有收到回调？**
回调是独立链路，请参考《接口回调链路 - 说明文档》，确认调用时传了 `notifyUrl` 或在平台配置了回调地址。
